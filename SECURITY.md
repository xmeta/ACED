# Security Policy

## Supported versions

The `main` branch is the currently supported development line. A release or
maintenance branch is supported only when it is explicitly identified in the
repository's release documentation. If you are unsure which version is
affected, include the commit or release tag in a private report.

## Reporting a vulnerability

Please do not open a public GitHub Issue for a suspected vulnerability.

Use GitHub Security Advisories' private vulnerability reporting for this
repository. Include the affected commit or tag, impact, reproduction steps,
and any safe mitigation or proof-of-concept that is necessary to reproduce the
issue. Remove credentials, tokens, and personal data from the report.

If private vulnerability reporting is unavailable, contact the repository
maintainers through a private GitHub channel before making any disclosure.

## Response targets

The maintainers aim to acknowledge a report within 5 business days and provide
an initial triage or status update within 10 business days. These are response
targets rather than guarantees; remediation timing depends on severity,
reproducibility, affected versions, and the availability of a safe fix.

Please allow maintainers reasonable time to investigate and release a fix
before public disclosure. Coordinated disclosure details can be agreed with
the reporter after triage.
